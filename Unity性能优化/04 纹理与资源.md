# 04 纹理与资源

本模块为归纳后的原理与实践建议。历史原问集中在 [[历史问题索引]]；无原文支持的扩展不视为用户问过。

## ASTC与纹理内存

ASTC 每块固定 128 bit；块尺寸越大，码率越低，通常也越损失细节。基础层估算为 ceil(W/bx) × ceil(H/by) × 16 字节；完整 mip 链近似增加三分之一，实际还受小 mip、对齐和格式影响。

**验证与验收：** 对同一纹理比较 ASTC 4×4、6×6、8×8 的细节与真机内存。

## 格式回退与平台

不支持目标压缩格式时可能发生回退或解压，增加内存与加载成本。平台导入设置、图形 API 和设备能力必须一起核对，不能只看磁盘文件大小。Read/Write 可能保留 CPU 副本。

**验证与验收：** 在目标设备核对实际 graphicsFormat、尺寸、mipmapCount 与快照。

## SpriteAtlas与合图

图集通过共享纹理减少切换，但 Canvas、材质、裁剪、排序和 Shader 等仍能拆批。过大的图集会把互不同时使用的内容一起驻留；Padding 和 mip 影响边缘渗色。

**验证与验收：** 按共同加载生命周期拆图集，测界面切换时纹理驻留与批次。

## Mip与资源预算

Mip 降低远处采样带宽和闪烁，但增加存储；纹理流送按需求控制 mip 驻留。纹理、网格、音频与 Shader 要有独立预算，最终同时检查总峰值。

**验证与验收：** 为目标机型制定纹理、网格、音频预算和加载峰值阈值。

## ASTC 数值与流送粒度（Q037–Q040）

ASTC 6×6 的码率为 `128/36 ≈ 3.56 bit/pixel`，不是降低图像宽高。1024×1024 基础层用 `ceil(1024/6)^2*16 = 467856 bytes ≈ 456.89 KiB`；4×4 为 1 MiB，节省约 55.38%。不能把该比例当作 GPU 耗时收益。完整 mip 链必须逐层向上取整求和，尤其小尺寸不能只套 4/3。

启用 Streaming Mip Maps 需要生成 mip 并配置 Quality 与纹理设置。预算是流送系统预算，不是整个进程显存硬上限；GPU 选择采样哪级 mip 与系统是否卸载高分辨率 mip 是两件事。突然转镜头需观察模糊恢复与上传峰值。VT 的页表、反馈、缓存和格式对齐见 [[GPU Driven与虚拟化技术#两种纹理流送]]。
