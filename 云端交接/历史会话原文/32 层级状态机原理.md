下面给你一个 **Unity 里可直接挂到 `MonoBehaviour` 的层级状态机版本**，尽量保持简单、能跑、好改。

这个版本的思路是：

- `StateMachine` 挂在角色对象上
- 状态本身不继承 `MonoBehaviour`
- 通过 `Update()` 每帧把输入事件喂给状态机
- 状态切换时，自动处理父状态的 `Enter / Exit`

using UnityEngine;

public abstract class State
{
    public State Parent { get; private set; }

    protected State(State parent)
    {
        Parent = parent;
    }

    public virtual void Enter()
    {
        Debug.Log($"Enter {GetType().Name}");
    }

    public virtual void Exit()
    {
        Debug.Log($"Exit {GetType().Name}");
    }

    public virtual bool Handle(StateMachine fsm, string evt)
    {
        if (Parent != null)
            return Parent.Handle(fsm, evt);

        return false;
    }
}

## 2）状态机本体

```csharp
using System.Collections.Generic;
using System.Linq;
using UnityEngine;

public class StateMachine
{
    public State CurrentState { get; private set; }

    public void Start(State leafState)
    {
        CurrentState = leafState;

        var path = GetPathRootToLeaf(leafState);
        foreach (var state in path)
        {
            state.Enter();
        }
    }

    public void SendEvent(string evt)
    {
        if (CurrentState == null)
            return;

        Debug.Log($"Event: {evt}");

        if (!CurrentState.Handle(this, evt))
        {
            Debug.Log($"No state handled event: {evt}");
        }
    }

    public void ChangeState(State targetState)
    {
        if (CurrentState == targetState)
            return;

        var currentPath = GetPathRootToLeaf(CurrentState);
        var targetPath = GetPathRootToLeaf(targetState);

        int common = 0;
        while (common < currentPath.Count &&
               common < targetPath.Count &&
               currentPath[common] == targetPath[common])
        {
            common++;
        }

        for (int i = currentPath.Count - 1; i >= common; i--)
        {
            currentPath[i].Exit();
        }

        for (int i = common; i < targetPath.Count; i++)
        {
            targetPath[i].Enter();
        }

        CurrentState = targetState;
    }

    private List<State> GetPathRootToLeaf(State state)
    {
        var stack = new Stack<State>();
        while (state != null)
        {
            stack.Push(state);
            state = state.Parent;
        }
        return stack.ToList();
    }
}
```

## 3）具体状态

```csharp
using UnityEngine;

public class CharacterState : State
{
    public CharacterState() : base(null) { }
}

public class GroundState : State
{
    public IdleState IdleState;
    public RunState RunState;
    public JumpState JumpState;

    public GroundState(State parent) : base(parent) { }

    public override bool Handle(StateMachine fsm, string evt)
    {
        if (evt == "Jump")
        {
            fsm.ChangeState(JumpState);
            return true;
        }

        return base.Handle(fsm, evt);
    }
}

public class AirState : State
{
    public IdleState IdleState;

    public AirState(State parent) : base(parent) { }

    public override bool Handle(StateMachine fsm, string evt)
    {
        if (evt == "Land")
        {
            fsm.ChangeState(IdleState);
            return true;
        }

        return base.Handle(fsm, evt);
    }
}

public class IdleState : State
{
    public RunState RunState;

    public IdleState(State parent) : base(parent) { }

    public override bool Handle(StateMachine fsm, string evt)
    {
        if (evt == "Move")
        {
            fsm.ChangeState(RunState);
            return true;
        }

        return base.Handle(fsm, evt);
    }
}

public class RunState : State
{
    public IdleState IdleState;

    public RunState(State parent) : base(parent) { }

    public override bool Handle(StateMachine fsm, string evt)
    {
        if (evt == "Stop")
        {
            fsm.ChangeState(IdleState);
            return true;
        }

        return base.Handle(fsm, evt);
    }
}

public class JumpState : State
{
    public JumpState(State parent) : base(parent) { }
}
```

## 4）挂在 Unity 物体上的 MonoBehaviour

```csharp
using UnityEngine;

public class CharacterControllerHSM : MonoBehaviour
{
    private StateMachine fsm;

    private CharacterState root;
    private GroundState ground;
    private AirState air;

    private IdleState idle;
    private RunState run;
    private JumpState jump;

    private void Awake()
    {
        root = new CharacterState();

        ground = new GroundState(root);
        air = new AirState(root);

        idle = new IdleState(ground);
        run = new RunState(ground);
        jump = new JumpState(air);

        ground.IdleState = idle;
        ground.RunState = run;
        ground.JumpState = jump;

        air.IdleState = idle;

        idle.RunState = run;
        run.IdleState = idle;

        fsm = new StateMachine();
        fsm.Start(idle);
    }

    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.W))
        {
            fsm.SendEvent("Move");
        }

        if (Input.GetKeyDown(KeyCode.S))
        {
            fsm.SendEvent("Stop");
        }

        if (Input.GetKeyDown(KeyCode.Space))
        {
            fsm.SendEvent("Jump");
        }

        if (Input.GetKeyDown(KeyCode.L))
        {
            fsm.SendEvent("Land");
        }
    }
}
```

## 5）你在 Unity 里怎么用

把这个脚本挂到一个角色对象上，然后运行：

- 按 **W**：从 `Idle -> Run`
- 按 **Space**：从地面状态切到 `Jump`
- 按 **L**：从空中落回 `Idle`
- 按 **S**：`Run -> Idle`

控制台会打印出每次进入和退出的状态。

### 助手

你圈出来的 **“Unity 常见 AI HFSM”**，指的是很多 Unity 项目里的 AI 状态机实现都会采用 **层级状态机（HFSM）**，而不是简单的平面 FSM。

例如敌人 AI：

```text
AI
├── Combat
│   ├── Chase
│   ├── Attack
│   └── Retreat
└── NonCombat
    ├── Patrol
    ├── Idle
    └── Investigate
```

如果用普通 FSM，状态之间会出现大量转换：

```text
Patrol -> Chase
Patrol -> Attack
Patrol -> Retreat
Idle -> Chase
Idle -> Attack
...
```

状态越多，连线越爆炸。

而 HFSM 会把公共逻辑提取到父状态。

例如：

```text
Combat
├── Chase
├── Attack
└── Retreat
```

所有战斗状态共享：

```csharp
Combat.Update()
{
    LookAtTarget();
    CheckTargetLost();
    UpdateThreat();
}
```

子状态只关心自己的行为：

```csharp
Attack.Update()
{
    FireWeapon();
}
```

```csharp
Chase.Update()
{
    MoveToTarget();
}
```

### 为什么 Unity 项目喜欢 HFSM

因为 Unity 的很多系统天然有层级：

- Animator State Machine
- UI 状态
- 玩家状态
- AI 行为

例如角色：

```text
Run
Attack_Run
Skill_Run

Idle
Attack_Idle
Skill_Idle
```

如果用平面 FSM：

```text
Run
Attack_Run
Skill_Run
Idle
Attack_Idle
Skill_Idle
...
```

状态数量会呈乘法增长。

HFSM 可以拆成：

```text
Move
├── Idle
└── Run

Attack
├── NormalAttack
└── SkillAttack
```

从而减少状态数量和转换逻辑。

---

不过要注意一点：

很多 Unity 开源项目号称 HFSM，实际上只是：

```csharp
State Parent;
```

加上事件冒泡：

```csharp
CurrentState.HandleEvent();
Parent.HandleEvent();
```

这种只能算“半层级状态机”。

严格的 HFSM 通常需要：

```csharp
State ActiveChild;
```

维护一条完整的活跃路径：

```text
AI
 -> Combat
 -> Attack
```

并支持：

```text
Enter
Update
Exit
```

在整条路径上传递。

像 UML Statechart、QP Framework、Unity 商业 AI 框架中的 HFSM 实现，通常都会采用这种完整结构。
