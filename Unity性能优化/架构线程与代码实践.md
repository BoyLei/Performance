# 架构线程与代码实践

## Callback与UniTask

来源：[[历史问题索引#Unity异步方案对比]]。复杂业务顺序可使用 UniTask 表达，持续广播与底层兼容接口仍可保留事件或 Callback。适配层必须明确取消、异常与完成次数，不能认为换语法就获得性能收益。

## 无状态与线程安全

来源：[[历史问题索引#分支 · 讲解 Unity 内存原理]]。无实例字段不等于线程安全；静态缓存、对象池、共享缓冲区、原生解析库和输入对象都可能共享可变状态。并行解析应各自拥有输出与临时缓冲，查清依赖库契约，再把表现层操作交回 Unity 主线程。

## Timer与GC纠错

最小堆解决找最近触发时间的复杂度，不使主线程免受 GC 停顿。System.Threading.Timer 通常在线程池回调，也不能保证实时性，更不能直接调用普通 Unity 对象 API。暂停后补触发需要上限，避免一次执行堆积回调。

值类型的存储位置取决于容器与逃逸、装箱等因素，不能概括为 struct 一定在栈。foreach 是否分配取决于枚举器和接口路径，RemoveAt 主要是搬移成本，不应一概归为 GC 分配。

## MVC MVP MVVM与依赖

MVC 组织模型、视图与控制器；MVP 用 Presenter 驱动视图接口；MVVM 用 ViewModel 和绑定同步状态。依赖倒置是高层与低层依赖抽象的设计原则，依赖注入是提供依赖的方式之一。框架选择不能替代事件解绑与生命周期约束。

PropertyChangedEventArgs 可按属性名缓存不可变实例，避免每次通知新建；不同属性不能总用同一个错误名称。去掉重复通知往往比只缓存参数更有价值。

## HFSM

父状态维护活动子状态，切换时从旧分支退出到公共祖先，再进入新分支。父级是否持续更新、事件先给子还是先给父、重入和中途切换规则都要明确。历史代码曾出现父子状态未真正连接的问题，应以状态迁移测试验收。

## 包版本与xLua

Shader Graph、SRP Core、URP 的依赖必须按包声明及 Editor 版本配套，不能直接将本地旧 Core 与较新 Shader Graph 强配。历史截图未包含像素，无法重现具体报错。

归档历史问过 Lua 改成 `.lua.txt`：常见用途是让 Unity 按 TextAsset 导入，再由 xLua 自定义 loader 读取；后缀不改变 Lua 语义，也不意味着加密。Addressables/Bundle 地址约定应与加载器一致。
